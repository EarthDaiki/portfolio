Overview

  • Minefia TaskXP is a desktop task management app built with Tauri, React, TypeScript, Rust, and SQLite.
  • Developed a complete prototype with local task management, tag management, calendar views, settings, and secure API key management.
  • Implemented AI Quick Add using the OpenAI Responses API to convert natural language into editable task drafts.
  • Designed the app as a local-first productivity tool that stores task data locally while keeping OpenAI API keys in the OS keychain.

Key Features

  • Create tasks with title, description, priority, difficulty, estimated minutes, due date, due time, and tags.
  • View tasks by list, today, upcoming, completed, calendar, and tag.
  • Open a task detail page to inspect and edit task data.
  • Complete, restore, start, and reset task progress.
  • Track started time, completed time, estimated minutes, and actual minutes.
  • Add, select, display, and delete tags.
  • Manage OpenAI API keys from the Settings page.
  • Store API keys in the OS keychain through the Tauri backend.
  • Use AI Quick Add to convert natural language into an editable task draft.
  • Store task data locally with SQLite.

Tech Stack

  • Desktop Framework: Tauri
  • Frontend: React, TypeScript, Vite
  • Backend Runtime: Rust through Tauri commands
  • Database: SQLite
  • Calendar: FullCalendar
  • AI API: OpenAI Responses API
  • Security: OS keychain integration for OpenAI API key storage
  • Platform: Cross-platform desktop application prototype

Architecture / Workflow

Task Management Flow:

  • User creates or edits a task from the desktop UI.
  • Task fields include title, description, priority, difficulty, estimated minutes, due date, due time, and tags.
  • The task can be viewed through list, today, upcoming, completed, calendar, and tag-based views.
  • User can start, complete, restore, or reset task progress.
  • The app tracks started time, completed time, estimated minutes, and actual minutes.
  • Task and tag data are stored locally with SQLite.

AI Quick Add Flow:

  • User writes a natural language prompt such as Cook dinner today at 7pm.
  • The app sends the prompt to the OpenAI Responses API.
  • The API returns a structured task draft with fields such as title, description, due date, due time, priority, difficulty, estimated minutes, existing tags, and suggested tags.
  • The AI result is opened in the task dialog instead of being saved automatically.
  • User reviews, edits, and manually saves the generated task draft.

Settings & Storage Flow:

  • User can add, select, and delete OpenAI API keys from the Settings page.
  • API keys are stored in the OS keychain through the Tauri backend.
  • SQLite stores only key metadata such as display name and which key is selected as the main key.
  • The Settings page also supports tag management.

Design Considerations:

  • Kept task data local with SQLite to support a desktop-first workflow.
  • Used the OS keychain for API key storage so sensitive keys are not stored directly in SQLite.
  • Designed AI Quick Add as an assisted workflow where users remain in control before saving generated task data.
  • Used Tauri to combine a React frontend with Rust-backed desktop capabilities.

Challenges & Solutions

① Converting natural language into safe task drafts

Problem:

  • AI-generated task data can be useful, but saving it automatically could create incorrect tasks or unwanted metadata.

Solution:

  • Implemented AI Quick Add as an editable draft flow.
  • Opened the generated result in the task dialog so the user can review, edit, and save it manually.

② Protecting OpenAI API keys in a desktop app

Problem:

  • The app needed to store user API keys without keeping the raw key values in the local SQLite database.

Solution:

  • Stored API keys in the OS keychain through the Tauri backend.
  • Stored only non-sensitive key metadata in SQLite, such as display name and main key selection.

③ Supporting multiple task views and tags

Problem:

  • Tasks needed to be accessible from different workflows, including list, today, upcoming, completed, calendar, and tag-based views.

Solution:

  • Implemented multiple task views over the same local task data.
  • Added tag creation, selection, display, and deletion to support flexible organization.

④ Tracking real task progress

Problem:

  • A task app needs more than a complete checkbox when users want to compare estimated and actual effort.

Solution:

  • Tracked started time, completed time, estimated minutes, and actual minutes.
  • Added start, complete, restore, and reset actions for task progress.

Result / Outcome

  • Completed a working prototype of a desktop task management app with local SQLite storage.
  • Implemented task management, tag management, calendar views, settings, API key management, and AI Quick Add.
  • Built a secure API key storage flow using the OS keychain through the Tauri backend.
  • The project is not production-ready yet, but the main task management flow and AI-assisted quick add workflow are implemented.
