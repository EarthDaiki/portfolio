Minefia LAN File Transfer

Demo / Links

  • GitHub: View Repository
  • Status: Early development. Tested locally on a single computer; transfers between separate LAN devices have not yet been verified.
  • Getting Started: Run go run ./receiver and go run ./sender from separate terminals.

Overview

  • Minefia LAN File Transfer is an early Go prototype for exploring TCP networking, file I/O, and concurrent programming.
  • The current sender and receiver establish a TCP connection locally, transfer file contents, and save the received data to a local file.
  • The prototype has been tested on one computer. Transfers between separate devices on a LAN are not yet verified.

Key Features

  • Send file contents over a TCP connection.
  • Receive data and save it to a local file.
  • Display the number of bytes transferred.
  • Run the sender and receiver independently from separate terminal windows.

Tech Stack

  • Language: Go
  • Networking: TCP with Go net.Listen and net.Dial
  • File Transfer: Go standard library io.Copy
  • Structure: Separate sender and receiver programs

Architecture / Workflow

File Transfer:

  • Start the receiver and sender independently in two terminal windows.
  • The programs establish a local TCP connection and stream file contents from sender to receiver.
  • The receiver saves the received data to a local file; the output filename is determined by its implementation.
  • The current sender expects a file named text.txt unless its source is changed.

Project Structure:

  • The repository separates sender-side and receiver-side code into dedicated components.
  • The project is implemented in Go and uses the Go module system.
  • Goroutines, channels, multiple simultaneous connections, transfer verification, and automatic device discovery are planned improvements, not current features.

Challenges & Solutions

① Coordinating transfers between devices

Challenge:

  • The initial prototype needed to establish a working sender-to-receiver TCP flow and transfer file bytes.

Approach:

  • Use Go's TCP networking APIs and io.Copy to transfer data between separate sender and receiver programs.

② Supporting concurrent transfer work

Challenge:

  • Concurrent connections and transfer progress reporting are not implemented in the current prototype.

Approach:

  • Goroutines and channels are identified as future work for concurrent connections and progress reporting.

Result / Outcome

  • Built a local TCP sender/receiver prototype that transfers a small text file between two processes on one computer.
  • Established a foundation for exploring network file transfer in Go; cross-device LAN support remains unverified.
  • Authentication, encryption, and robust interrupted-transfer recovery are not implemented. Use only in a trusted local testing environment.
  • Concurrent transfers, progress channels, metadata, integrity checks, device discovery, and a GUI are planned improvements.
  • The source code is available in the project repository.
