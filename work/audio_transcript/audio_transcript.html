Overview

  • Minefia Audio is a Tauri desktop app that sends audio to the OpenAI Audio Transcriptions API, displays transcript text as it streams, and exports completed transcripts.
  • It supports audio from local files, system audio, a microphone, YouTube and URLs, HLS streams, and web pages.
  • Users can also translate transcripts, generate summaries and study notes, and ask questions using transcript context.
  • Audio files and transcripts are managed in app storage and can be reviewed from the in-app Library.

Key Features

  • Stream live transcript text while audio transcription is in progress.
  • Capture System Audio on macOS, Windows, and Linux, or record from a selected microphone.
  • Use Live Mode for real-time captions, with partial and final transcription events and reconnect handling.
  • Inspect local audio and video, select an audio track, preserve compatible source codecs, and split long audio near silence into ordered parts.
  • Resume interrupted file transcription jobs from saved chunk checkpoints; retry temporary network failures and rate limits.
  • Inspect YouTube, direct media URLs, HLS playlists, and web pages for available media streams before extraction.
  • Translate completed transcripts, produce incremental Markdown notes and a final summary, and ask questions using transcript and summary context.
  • Manage multiple OpenAI keys and Projects, validate keys before saving, and view aggregated usage where supported.
  • Estimate transcription and text-processing costs before starting optional API work.
  • Browse, preview, open, and delete app-managed recordings and transcript files in the Library.

Tech Stack

  • Desktop Framework: Tauri
  • Frontend: React
  • Backend: Rust
  • Transcription: OpenAI Audio Transcriptions API and Realtime transcription
  • Text Processing: OpenAI Responses API
  • Audio and Media: FFmpeg, ffprobe, yt-dlp, and Chromium for isolated web-page inspection
  • Credential Storage: Operating-system Keychain
  • Audio Capture: Core Audio, WASAPI Loopback, and PipeWire

Architecture / Workflow

Transcription Workflow:

  • The app inspects the selected source and its audio streams before processing.
  • When needed, audio is extracted or explicitly confirmed for conversion, then split into size-limited chunks around quiet sections.
  • Chunks are transcribed with bounded concurrency, retries, and checkpoints; completed results are merged in source order.
  • Streaming events update transcript text as the API returns it.

Capture Modes:

  • Standard Mode buffers captured audio and splits at quiet sections after a 90-second minimum, with a 150-second hard limit.
  • Live Mode streams mono PCM to a Realtime transcription session and commits turns using client-side speech-end detection.
  • Captured recordings are retained in app data, including while Live Mode is active.

Storage & Credentials:

  • API key secrets stay in the system Keychain; the frontend does not receive them.
  • Recordings, extracted media, transcripts, summaries, and resumable job checkpoints are stored in app-managed data locations.
  • Local media can be referenced by path without copying; confirmed deletion of a referenced Library item deletes its source file.

Challenges & Solutions

① Processing long recordings reliably

Challenge:

  • Long or variable-bitrate audio can exceed request limits, and interrupted uploads should not require repeating completed work.

Approach:

  • Split audio near silence, recheck oversized segments, checkpoint completed chunks, and retry temporary failures with backoff.

② Supporting desktop audio capture across platforms

Challenge:

  • System audio and microphone capture use different native APIs and have platform-specific permissions and device availability.

Approach:

  • Use platform-native capture backends and a shared queue with silence-based chunking, concurrency controls, and explicit device and permission handling.

③ Handling variable online media sources safely

Challenge:

  • Websites expose media differently, and an inspected source may still fail to download or decode.

Approach:

  • Inspect available streams before extraction, use a private Chromium profile for web pages, block private-network browser requests, and do not bypass DRM or access controls.

Result / Outcome

  • Built a cross-platform desktop prototype for transcription workflows spanning local files, live capture, and online media.
  • Added streamed transcript rendering, resumable chunk processing, translation, summaries, study notes, and transcript Q&A.
  • Designed media retention, Keychain-based credentials, cost estimates, and source-access limitations into the workflow.
  • The project remains a prototype. Media compatibility and online source availability can vary, so important recordings and transcripts should be backed up.
